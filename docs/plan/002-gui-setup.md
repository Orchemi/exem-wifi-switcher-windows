# 002: EXE 설치와 현재 회사 설정 가져오기

## 사용자 흐름

Setup.exe를 더블클릭하고 관리자 승인 후 현재 회사 Wi-Fi의 고정 IPv4·서브넷·게이트웨이·DNS를 읽습니다.
사용자가 감지된 값이 회사 설정임을 확인하면 관찰 모드로 설치합니다.
자동 전환 켜기를 승인하면 현재 값과 서비스 계정의 감지 결과를 확인한 뒤 활성화합니다.
숫자 입력·JSON 편집·터미널 실행은 필요하지 않습니다.

## 구현 계약

- 단일 self-contained WinForms WinExe, requireAdministrator manifest, 내장 런타임 ZIP.
- 감지: 현재 연결 Wi-Fi 하나, 고정 IPv4 하나, 기본 게이트웨이 하나, 수동 DNS만 지원.
- DHCP, SSID 미확인, 다중 연결·주소, 사용자 지정 라우트, 미준비 주소는 자동 등록하지 않습니다.
- 두 번의 SSID 확인으로 감지 도중 연결 변경을 확인하고 설치·활성화 직전 실제 값을 재조회합니다.
- 서비스 관찰 결과가 최신이고 현재 구성과 일치해야 활성화합니다. PC 사용자의 조회 성공만으로 충분하지 않습니다.
- 설치 로직은 기존 PowerShell 스크립트 하나를 유지합니다. GUI는 사용자 승인 뒤 숨겨진 프로세스로 호출합니다.
- 실행 정책은 자식 프로세스의 RemoteSigned만 사용합니다. GPO·AppLocker·WDAC를 해제하지 않습니다.
- 설치 자료와 임시 캡처는 관리자/SYSTEM만 접근하는 임의 이름의 Program Files 하위 디렉터리에 풉니다.
- 실제 값은 로컬 화면·보호된 파일에만 둡니다. 자식 프로세스 출력과 원본 예외는 외부 진단으로 노출하지 않습니다.
- 다시 연 설치 화면에서 중지·DHCP 복귀·최초 백업 복원·제거를 제공합니다.
- 중지·복구는 observe로 저장하여 다음 부팅에서 enforce가 다시 켜지지 않게 합니다.
- 기존 설치는 덮어쓰지 않습니다. 이번 범위에 자동 업데이트는 포함하지 않습니다.

## 한계와 검증

핵심 정책 단위 테스트, 읽기 전용 캡처의 네트워크 변경 방지 테스트, GUI 확인을 받은 스크립트의 무입력 실행 테스트를 수행합니다.
Mac에서는 크로스 빌드와 패키지 검사만 가능합니다. Windows UI·UAC·실제 무선랜 전환은 실기 검증이 필요합니다.
마지막 확인과 실제 적용 사이의 Wi-Fi 변경을 원자적으로 막는 기능은 없습니다.
